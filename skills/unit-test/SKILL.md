# 单元测试编写规范

## 工作流

1. 先读取 `AGENTS.md`、被测实现和现有测试，确认公开行为与项目约定。
2. 将测试放在 `tests/` 下，并命名为 `test_<module>.py`。
3. 每个测试只验证一个行为，按 Arrange、Act、Assert 组织。
4. 先运行最小相关测试，再运行完整测试套件；失败时报告命令和关键错误。

## 命名与覆盖

- 用场景和预期结果命名测试，例如 `test_calc_order_total_with_multiple_items`。
- 覆盖正常路径、边界条件和异常输入；金额与数量逻辑至少考虑空列表、零数量、负值和舍入边界。
- 用 `pytest.raises` 验证预期异常，并尽量断言异常类型和稳定的错误信息。
- 为缺陷修复先添加能复现问题的回归测试。

## 金额断言

- 用 `Decimal` 构造金额和期望值，禁止用 `float` 参与货币运算。
- 优先断言精确的 `Decimal` 结果；仅在业务规则明确要求时量化小数位。

## 接口测试

- 同时验证 HTTP 状态码、响应体和对外 camelCase 字段。
- 覆盖无效请求、业务错误以及不应泄露的内部字段。
