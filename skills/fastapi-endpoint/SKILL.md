# FastAPI 接口编码规范

## 工作流

1. 先读取 `AGENTS.md`、相关路由、模型、业务逻辑和现有测试。
2. 将业务计算留在领域模块中；路由只负责输入校验、调用业务逻辑和构造响应。
3. 同步添加或更新 pytest 测试，覆盖成功、边界和错误路径。
4. 先运行最小相关测试，再运行完整测试套件；失败时报告命令和关键错误。

## 路由

- 用 `APIRouter` 按资源分模块，路径使用复数名词，例如 `/orders`。
- 用 HTTP 方法表达动作，避免在 URL 中添加不必要的动词。
- 显式声明 `response_model` 和恰当的成功状态码。

## 请求与响应模型

- 入参与出参使用带类型注解的 Pydantic 模型，禁止以裸 `dict` 作为公开契约。
- Python 字段使用 snake_case；通过 Pydantic alias 对外暴露 camelCase，并确保响应按 alias 序列化。
- 金额字段使用 `Decimal`，禁止转换为 `float` 进行计算。
- 响应模型只包含公开字段，避免泄露内部标识、异常或实现细节。

## 错误处理

- 将可预期的业务错误映射为语义正确的 HTTP 状态码和简短、稳定的 `detail`。
- 不把堆栈、数据库错误或其他内部异常信息直接返回客户端。
- 让 Pydantic 处理结构与字段校验；仅在需要业务语义时添加额外校验。

## 验证

- 测试状态码、响应体、camelCase 别名、金额精度、无效输入和业务错误。
- 检查 OpenAPI 中的请求与响应契约是否与实现一致。
